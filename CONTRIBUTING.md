# Contributing

For anything beyond a typo or a one-line documentation fix, describe the problem before proposing the patch. A reviewer needs to know:

- what is wrong or missing
- how you know, with a file, a reproduction or a failing case
- what goes wrong because of it
- the smallest change that fixes it
- what the change does not cover

If a change is large, or touches a specification, a wire format or conformance vectors, consider opening an issue first so the problem and scope can be checked before time goes into the fix.

Some repositories require a DCO sign-off on every commit (`git commit -s`). A repository with its own CONTRIBUTING file follows that file instead of this one.

Maintainers work through the same questions in more detail, in the [Contribution Brief](https://github.com/aeoess/.github/blob/main/CONTRIBUTION-BRIEF.md).
